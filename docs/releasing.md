# Releasing

**Lineages to update.** A fix in a stub reaches an app only through `kit:update`; `composer update` alone leaves it unapplied. When you rename `## Unreleased` to the new version, run `php bin/release-lineages.php` and put its output first under the new heading. It compares the feature pins in `src/Catalog.php` at HEAD with the newest `vX.Y.Z` tag before HEAD (or `php bin/release-lineages.php <from-ref> [<to-ref>]`) and prints ``Run `php artisan kit:update` for: <lineages>``, the lineages in canonical order, or that no pin changed. A new feature gets its own `kit:add` line. It exits 1 when either ref's `src/Catalog.php` cannot be read.

**Form payloads.** A change to what a kit form submits (a field removed or renamed, or a form's fixture removed) is breaking: release it as a minor, not a patch, with an upgrade note, and add a line `Form payload: breaking` under `## Unreleased` in CHANGELOG.md. Added fields are not breaking, since the server drops undeclared fields. `php bin/form-payload-check.php <previous-tag>` compares the field names in `tests/fixtures/form-payloads/` with that release; the `Form payloads` CI job runs it on every pull request against the merge base with main.
