# Browser job

`run.mjs` runs the kit's real-browser checks: Playwright (Chromium) over a Vite build of the core component stubs, with axe-core for accessibility.

```sh
cd browser
npm ci
npx playwright install chromium
node --test run.mjs
```

The pages are in `src/`, picked by query string (`?alert-layout`: an Alert with actions below (the default) and inline, and a locked FormCard with its notice and with `hideLockFooter`, with `KIT_ALERT_SCREENSHOT=<path prefix>` saving the inline run at 1280 and 390px; `?workbench`, `?workbench-menu`, `?workbench-reorder`: a reorderable Workbench over a stand-in for Inertia v3's HTTP client, whose bodies are strings and whose server refuses a stale or null version); `?fill-all` (`&dark`): ActionBar with `fill-all` on a pill surface, with disabled actions, the default pill, a menu-only bar with `menu-trigger-label` unset, `Trip` and null (read at 390px for the text and the null trigger's "More actions" name), a menu-only and a compacted bar with `trigger-class="-ml-px rounded-l-none"` read on ButtonGroup's trigger, and a GET action with intent `panel`, read for fill, radius, padding, label weight, the divider between segments, a `divider-class` one, the divider at the outline token (20%), a `trigger-class` trigger (42px, ringed) with `divider-class="border-r-0"` in the full and the compact layout, the ⌄ trigger's padding, dimming, axe with contrast on the filled pills and a button that emits; `?item-class`: an ActionBar with `item-class="min-h-12"`, its More menu's rows read for height, the destructive colour and the disabled dimming, and a ButtonGroup with and without `item-class="gap-2 px-4 py-2"` around DropdownItem and DropdownLink rows (button, anchor, Inertia link) and a DropdownModalLink, read for one padding and the same height; `?collection-section` (`&dark`): CollectionCard and CollectionSection (docs/collection-section.md): on CollectionCards, a list with segment tabs, a Sort by menu, a header action and 30 rows scrolling past a 12rem `maxHeight` under its footer see-all, a stat card with its see-all in the header with a count and a plain title (`linkTitle: false`), an empty card with the descriptor's empty state and one with the `#empty` slot; the kit's stubs are copied into `.kit` and built against `kit.css`'s default tokens. `@/components/ui/button` is the host's real shadcn-vue Button (`src/button`, with cva), so a variant paints its real classes (`primary` is `bg-primary`), and `@/components/ui/checkbox` the real Checkbox (`src/shadcn`); ## Contrast checks need a non-modal surface

Run axe's `color-contrast` on a non-modal surface. A modal menu or dialog sets `aria-hidden` on the rest of the page, and axe then skips that content, so a
contrast failure can pass unseen (a modal menu reports `aria-hidden-focus` and the landmark rules instead). The Workbench row menu is non-modal, so its open-menu
run checks the destructive Delete item's contrast on the popover.

## The suite has a floor

`expected-count` holds the number of browser tests the suite must keep. `node count-check.mjs` fails when `run.mjs` declares fewer, and CI runs it again on the TAP report (`node count-check.mjs browser-tap.txt`), so fewer tests run or passed fails too. Raise the floor with each new test; a merge resolution that drops tests then fails CI instead of passing with a smaller suite.
